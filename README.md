# StageArtPlugIn

StageArtの主要な舞台活動機能を、既存のWordPressサイトへ導入できる形で提供するための独立プラグインです。

## 方針

StageArt本体の設計を参照しつつ、WordPress固有の実装とStageArtの業務モデルを分離します。

WordPressサイト自体を舞台芸術団体のサイトとして扱い、団体を別CPTや別URLとして二重管理しない方針です。

基本構成は以下です。

```text
WordPress Site
├─ 団体情報
├─ 連絡先
├─ メンバー
├─ 公演
├─ お知らせ
├─ トップページ
└─ メニュー
```

## メンバー

メンバーは独立したコンテンツ種別です。

```text
メンバー
├─ メンバー一覧
├─ ○○
├─ ××
└─ △△
```

「メンバー一覧」はシステムが標準で提供する一覧コンテンツです。
メンバーを追加するたびに個人コンテンツが増えていき、各個人コンテンツは独立した個人ページを持ちます。

個人コンテンツはトップページやメニューなど、サイト内の任意の場所から直接配置・参照できます。「看板役者」などの用途別コンテンツを別途作成する必要はありません。

標準項目:

- 名前（必須）
- Slug（システムで自動生成。編集可能）
- 写真
- 役割
- プロフィール
- SNS
- 劇団共通自由記述項目
- 表示順

役割は以下のプリセットから複数選択します。

- 俳優
- 演出
- 脚本
- 制作
- 音響
- 照明
- 舞台監督
- 劇団代表

詳細なメンバーコンテンツ仕様は `docs/Members.md` を参照してください。

### 劇団共通の自由記述項目

メンバーの追加項目は、劇団全体で共通する項目定義として管理します。

各項目は、項目名・説明・有効/無効・表示順を持ち、各メンバーはその項目に対する入力値を保持します。

- 追加: 全メンバーに新しい空欄項目を追加
- 編集: 項目名・説明などを変更。内部IDと既存入力値は維持
- 並び替え: 全メンバーに共通する表示順を変更
- 無効化: 編集画面と公開ページから非表示。既存入力値は削除せず保持
- 再利用: 無効項目を再び表示。以前の入力値をそのまま復活
- 完全削除: 初期版では通常機能として提供しない

無効化・再利用時の確認メッセージ、表示場所、入力データの扱いについても仕様化しています。

## 劇団代表挨拶

「劇団代表挨拶」はメンバー個人コンテンツとは別の独立コンテンツです。

代表者として対象メンバーを選択し、写真・名前・メンバーページへのリンクはメンバーコンテンツから自動取得します。挨拶本文のみを劇団代表挨拶側で入力します。

これにより、メンバー情報を複製せずに代表挨拶ページを作成できます。

## Production

公演は独立したコンテンツで、固有のSlugを持ちます。

公開URLは `/production/{production-slug}/` 形式とします。

公演本体（Production）と公演回（Performance）は別の概念として扱います。将来のチケット・予約機能との連動を考慮し、StageArt本体の `Production → Performance → Reservation / Ticket` の構造に準拠できるように設計します。

公演ページ自体はWordPress上の通常の公開コンテンツとして扱い、情報解禁日時によってページ公開状態を変更しません。公演本体、会場、公演回、メンバー一覧、チケット料金など、公開する情報単位ごとに情報解禁日時を設定できます。

公演期間は公演回（Performance）を基準として管理し、後の活動履歴への連携を可能にします。会場名はフリーテキストで管理し、Google Mapsで検索できる場合は検索結果の施設名称に近い名称で登録する運用とします。会場地図はGoogle Mapsを利用したコンテンツとして表示できるようにします。

出演者・スタッフは公演単位の情報として管理し、現時点ではAuthCore Userとの紐付けを必須としません。団体サイト内に該当する個人紹介ページが存在する場合のみ、そのページへのリンクを設定できます。チケット管理など、ユーザーを必要とする機能を導入する場合にAuthCore連携を追加します。

過去公演は別データモデルではなく、同じ公演コンテンツを日付・状態に応じて一覧表示するアーカイブビューです。

## 情報解禁日時

情報解禁日時は、公開コンテンツ単位で設定する共通仕様です。ページ自体は通常の公開状態にしたまま、アクセス時にPHPで解禁判定を行い、表示内容を切り替えます。

- 管理画面では日本時間（`Asia/Tokyo`）で入力する
- DBにはUTCの`DATETIME NULL`として保存する
- `NULL`は常時解禁済みを意味する
- 現在時刻が解禁日時以上になった時点で解禁済みとする
- PHPのデフォルトタイムゾーンには依存せず、タイムゾーンを明示する
- 情報解禁のためのcron、WP-Cron、予約公開による状態変更は行わない
- 未解禁時に何を表示するかは各コンテンツ側で決定する

詳細は `docs/ReleaseDate.md` を参照してください。

## StageArt本体との関係

StageArt本体では Core と Ticket / Rehearsal / Accounting などのDomain Moduleを境界づける設計方針が採用されています。このプラグインもその思想に従い、WordPress上で独立して利用できる構造を目指します。

## AuthCore

StageArtPlugInはAuthCoreを必要とする機能と、AuthCoreなしで成立する機能を分離して設計します。公演ページ・公演管理の基本機能はAuthCoreに依存せず、チケット・予約などユーザー認証を必要とする機能を追加する場合にのみAuthCoreとの連動を行います。
